# Why Nagare

Nagare begins with a dissatisfaction with the idea that digital banking means placing a modern application on top of a legacy operating model.

The project asks what changes if banking is designed natively for software from the beginning.

The objective is not only technical modernization. Nagare is interested in the operating economics of a bank: how much cost exists because of branches, fragmented systems, manual workflows, duplicated operations, reconciliation overhead, legacy vendors and old software assumptions?

A sufficiently low-cost bank could potentially pass efficiency to customers through better deposit economics, cheaper credit, better service and faster decisions while still operating a sustainable spread.

Nagare combines four ambitions:

1. **A digital-bank operating system** built from first principles.
2. **A living synthetic bank** that continuously exercises the stack.
3. **A hosted sandbox** that gives builders access to a complete fake bank.
4. **A bank-in-waiting** that can become production infrastructure if a suitable licensing regime emerges.

Nagare should be useful before any real bank is launched.
