# Nagare RFCs

Use an RFC when a proposed change materially affects the Constitution, contracts, kernel semantics, distributions, access-control model, financial semantics or cross-repository interoperability.

RFC lifecycle:

1. Draft
2. Discussion
3. Accepted or Rejected
4. Implemented
5. Superseded, if replaced

Accepted RFCs should not be silently rewritten to change history. Material changes should be represented by a new RFC.
